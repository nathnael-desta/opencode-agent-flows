# Agent guide

> **Keep `AGENTS.md` and `CLAUDE.md` identical.** They are mirrors, kept as two
> files only because different tools look for different names. If you change one,
> make the same change in the other in the same commit. A reviewer should never
> have to ask which one is authoritative.

## What this project is

`opencode-agent-flows` is an OpenCode plugin that decides **which agent uses
which provider, model, and reasoning effort**. Provider adapters live in their
own repositories; this project only routes work.

It does two things:

1. Ships built-in flows (`src/flows/`) that bind roles to specific models.
2. Lets a user generate their own flow from the models they actually have,
   ranked by **effective cost** and quality (`src/orchestration/`).

## Commands

```bash
bun install
bun run verify   # docs:check + bun test + tsc --noEmit — run before every commit
bun test         # tests only
bun run docs     # regenerate docs/flows/*.md after changing a flow definition
bun run setup    # interactive terminal setup for the orchestration config
```

`bun run verify` is the gate. Do not commit with it failing.

## Layout

| Path | Responsibility |
|---|---|
| `plugin.ts` | Entry point: the OpenCode `config` hook, all `flow_*` tools, run telemetry, guardrails |
| `src/flows/` | Declarative built-in `FlowDefinition`s |
| `src/orchestration/` | Data-driven custom flow: config, role templates, discovery, economics, quality |
| `src/telemetry/` | Run/session/global reports, pricing, quota, dashboard |
| `src/rift.ts` | Opt-in copy-on-write workspace isolation for parallel writers |
| `scripts/` | `generate-docs.ts`, `setup.ts` |
| `docs/` | Docsify site; `docs/flows/*.md` is generated, not hand-edited |

## Invariants — do not break these

- **Guardrails are plugin-owned.** A user's generated `orchestration-config.json`
  binds model/variant/billing and tunes budgets. It must never be able to weaken
  prompts, permissions, per-agent step budgets, protected paths, or escalation
  approval. Role templates in `src/orchestration/roles.ts` own those.
- **Untrusted config values are clamped, never trusted.** Flow-level budgets
  come from a file a user can hand-edit. `normalizeOrchestrationConfig` clamps
  them to sane ranges, because unbounded values can remove the concurrency limit
  or make every reviewer call throw, silently disabling the review gate.
- **A broken config must never disable the plugin.** `resolveFlow` degrades to
  the built-in flow, because throwing there unregisters every tool — including
  the ones needed to repair the config.
- **Never fuzzy-match model quality.** Exact match only; derivatives would
  inherit their flagship's score and invert every ranking.
- **Escalation requires approval.** `deep` and `extreme-*` need an explicit
  one-use `flow_approve_escalation` token, and `deep` needs concrete failed or
  blocked routine evidence first. Cheap-first is structural, not advisory.
- **Review is a milestone gate**, not a per-commit gate: one round normally, two
  maximum, at most five evidence-backed findings.
- **Malformed worker or reviewer output is an explicit failure.** Never spawn an
  extra model call just to repair formatting.
- **Telemetry stays backward compatible.** Persisted reports are versioned; keep
  `calls` as an alias for `assistantMessages` unless you design a migration.
- **Never hardcode a model** in new orchestration code. Models come from the
  user's config or discovery.

## Conventions

- TypeScript, ESM, `.js` extensions in relative imports (`./config.js`).
- No semicolons, double quotes, 2-space indent. Match the surrounding file.
- Comments explain *why*, not *what*. Keep them sparse.
- Prefer pure, injectable functions for anything touching the network so it can
  be tested with fixtures (see `discoverCatalog`'s `fetchText` parameter).
- Every network source must degrade: live → cache → bundled snapshot or omission.
  Discovery must always return something usable offline.

## Testing

- `bun test`, colocated in `tests/`.
- Add a test for each new behavior and each fixed bug.
- Network is never hit in tests; inject fake fetchers.
- The dashboard's rendering lives in an inline `<script>` that no typechecker
  sees. `tests/orchestration.test.ts` extracts and executes it against a
  document stub — keep that guard if you touch `src/telemetry/dashboard.ts`.

## Documentation

- `docs/` is a Docsify site; open it with `bun run docs:serve`.
- `docs/flows/*.md` is generated by `bun run docs`. Edit the flow definition,
  then regenerate; never hand-edit the output. `bun run docs:check` fails when
  generated docs are stale.
- Update `docs/CONFIGURATION.md` and `docs/FEATURES.md` when you add an option
  or capability.

## External data

- **models.dev** (`https://models.dev/api.json`) supplies pricing and
  capabilities. Costs are USD per 1M tokens.
- **Artificial Analysis** supplies model quality. Its documented API requires an
  account key even on the free tier, so we deliberately read the public models
  page instead, which embeds its charts as schema.org `Dataset` blocks in
  `application/ld+json`. Keep the attribution, cache aggressively, and keep the
  bundled snapshot fallback current.
